# PR #31 review: feat(auth): lock owner pin after five failed attempts per merchant

- **Reviewer:** 05-pr-reviewer (clean context)
- **Reviewed commit:** 0829f9e
- **Verdict:** PASS
- **Scope:** owner PIN lockout per merchant, migration `0001` (additive: table and foreign key), Postgres integration test with a guard for the test database, CI job, and ADR-013 (proposed).

## Result

- Each attempt is reserved before the PIN is compared, with one statement at a time: a conditional UPDATE, then an INSERT with ON CONFLICT DO NOTHING, then one retry UPDATE. Concurrent requests cannot pass the limit. This is covered by the Postgres integration test (10 concurrent calls, exactly 5 allowed).
- The database guard refuses query strings, fragments, whitespace, non-local hosts and database names outside `[a-z0-9_]+_test`. It is covered by unit tests.
- ADR-013 matches the code: five reservations start the lock, a correct PIN resets the count, expiry does not reset the count, and the lock is per merchant.

## Not verified here

- The lockfile has formatting churn from the local npm version. No package version changed.
- Lock rules are per merchant, so an operator can delay the owner's PIN for 15 minutes. This is a product decision, recorded in ADR-013 as proposed.
